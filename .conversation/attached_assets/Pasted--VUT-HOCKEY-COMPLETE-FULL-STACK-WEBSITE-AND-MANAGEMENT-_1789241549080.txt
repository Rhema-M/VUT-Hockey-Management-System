# VUT HOCKEY — COMPLETE FULL-STACK WEBSITE AND MANAGEMENT SYSTEM

Build a complete, professional, production-quality website and content management system for **VUT Hockey**.

The goal is to create the **entire working codebase** inside Replit, test that the application works correctly, and then export/push the completed project to GitHub.

**Replit is being used as the AI development and testing environment. It is NOT the required production hosting platform.**

After the project has been created and tested, I will continue development independently using:

* GitHub
* VS Code
* Python
* Flask
* MySQL

The final codebase must therefore be **portable and independent of Replit**.

---

# 1. VERY IMPORTANT: REQUIRED ARCHITECTURE

The application must follow a traditional full-stack architecture similar to a Flask/MySQL application.

Use:

```text
HTML + CSS + Vanilla JavaScript
              ↓
        Flask REST API
              ↓
           MySQL
```

The frontend communicates with the Flask backend using HTTP requests such as `fetch()`.

The Flask backend communicates with MySQL.

The browser must NEVER communicate directly with MySQL.

## DO NOT use:

* React
* React Router
* Next.js
* Vue
* Angular
* Svelte
* Node.js as the backend
* Express.js
* Firebase
* Supabase
* MongoDB
* Prisma
* Tailwind as the primary architecture
* Any framework that replaces the requested Flask architecture

Do not convert this project into a React application simply because that may be easier for the AI to generate.

The frontend must use:

* HTML
* CSS
* Vanilla JavaScript

The backend must use:

* Python
* Flask
* Flask REST API

The database must use:

* MySQL
* `mysql-connector-python`

Authentication must use:

* JWT
* Werkzeug password hashing

Other backend dependencies may include:

* `python-dotenv`
* `Flask-CORS`
* `PyJWT`

Keep the implementation understandable and maintainable by a Computer Systems Engineering student who is learning real-world full-stack development.

# 21. API RESPONSE FORMAT

Use a consistent response structure.

Success:

```json
{
    "success": true,
    "data": {}
}
```

Error:

```json
{
    "success": false,
    "error": "Description of the error"
}
```

Use appropriate HTTP status codes:

```text
200 OK
201 Created
400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
409 Conflict
500 Internal Server Error
```

Do not return inconsistent response formats between routes.
